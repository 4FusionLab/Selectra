# Selectra: выбор по примерам

## Задача

Пользователь показывает, что считает похожим, а Selectra предлагает выделение. Основной вход — один `Select Similar` в меню правой кнопки. Пользователь не должен начинать с выбора технической метрики.

**Область поиска зафиксирована пользователем 25.10.2026:** только тело выбранного примера. Несколько примеров допускаются из одного тела. При примерах из разных тел команда предлагает оставить примеры одного тела, а не расширяет поиск. Для экземпляров компонентов областью станет конкретное тело конкретного occurrence; геометрически одинаковое соседнее тело остаётся вне поиска.

## Основной сценарий

1. Выбрать одно или несколько рёбер либо граней одного тела.
2. ПКМ → `Select Similar`. Геометрия считывается после запуска команды, а не на каждом открытии меню.
3. Сразу увидеть лучший предложенный набор и число элементов. Примеры остаются в наборе. При неоднозначности — короткое объяснение.
4. Нажать `Select`; получить обычное выделение Fusion и продолжить работу, например запустить Fillet. `Cancel` восстанавливает исходный выбор при неизменном контексте.
5. Если результат не тот, уточнить примером или исключением. В текущем spike для второго примера нужно отменить команду и выбрать оба элемента до запуска. Добавление примеров внутри диалога и отрицательные примеры пока запланированы.

`Refine` свёрнут: уровень сходства `Tight / Balanced / Broad` и альтернативное объяснение набора. Первый запуск обходится без выбора критерия. Уровень пока меняет относительный размерный допуск; угол фиксирован 2°. Пользовательский угловой допуск требует проверки UX.

## Как выводится намерение

Вместо одного непрозрачного «расстояния похожести» строятся несколько объяснений. Каждое должно подходить ко всем примерам. Совпадающие наборы объединяются, затем ранжируются с учётом аналитического типа геометрии и чрезмерного охвата тела. Набор из одного примера и нескольких различных объяснений считается неоднозначным. Числовая оценка служит для порядка предложений, а не обозначает процент уверенности.

Примеры:

- Два прямых ребра разной длины, но одного направления → признак длины исключается, остаются параллельные рёбра.
- Два ребра одной длины с разным направлением → направление перестаёт ограничивать набор.
- Две цилиндрические грани одного радиуса с разными площадями → искать такой же радиус, не одинаковую площадь.
- Две плоские грани разных площадей с одинаковой нормалью → искать грани, обращённые в том же направлении.

Направление прямого ребра — ось: разворот параметризации на 180° ничего не меняет. Нормаль плоской грани — ориентированный вектор: противоположная сторона не считается той же ориентацией. У кривой поверхности одна произвольная нормаль не описывает направление целиком.

Если примеры не имеют устойчивого общего признака, инструмент сообщает об этом. Он не должен незаметно выбирать всё тело. Несколько разных размерных семейств одним набором примеров — отдельная будущая модель намерения; текущий алгоритм ищет общие признаки, а не объединение независимых семейств.

Mesh, T-Spline и эскизные сущности не входят в начальный BRep MVP. Для кривых поверхностей текущий код умеет лишь простые числовые сравнения площади/границы, а не распознавание формы.

## Инженерные решения из опыта Perfora

Ядро получает только неизменяемые снимки; перестановка примеров не меняет результат. Fusion adapter сохраняет исходный контекст. Никакие атрибуты не записываются на рёбра и грани. Модель не перестраивается, временные CAD-тела не создаются.

Сначала дешёвые аналитические признаки. Уточнение топологии и кривизны добавляется только там, где снижает ложные совпадения. Лимиты прототипа: до 10 000 сущностей тела и мягкий бюджет чтения 2 секунды. Проверка бюджета между API-вызовами не может прервать один долгий вызов; это защита от продолжения обхода, не гарантия задержки интерфейса. Массовая подсветка требует отдельного измерения.

Первую модель намерения реализуем локально и детерминированно. LLM для сравнения BRep не нужен. Адаптацию к привычкам пользователя можно исследовать позже на основе явных исправлений, не подменяя ей геометрические проверки.
