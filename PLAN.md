# План Selectra

Актуальное правило областей: This Body / This Component / All Components, по умолчанию This Component с вложенной иерархией выбранного экземпляра. Оно заменяет исходное ограничение одним телом. Исторические этапы ниже оценивать с учётом новой семантики [UX.md](docs/UX.md).

## Области сборки и подготовка к релизу — 25.10.2026

- Внедрены все три области, включая вложенную иерархию выбранного экземпляра и видимые экземпляры всей сборки. Proxy сохраняется для UI, чтение материала выполняется в нативной системе компонента, снимки/графика — в мировой.
- Ключи tempId из разных тел/экземпляров изолированы. Все ревизии и матрицы проверяются перед preview/OK и отложенным переносом выбора.
- Добавлены алиасы =/-, покрыта фактическая передача Shift раскладкой. Нативные переходы совпали с PgUp/PgDown.
- Пройден протокол на отдельной сборке с поворотами/вложениями и read-only проверка открытого пользовательского проекта. Результаты — [VALIDATION.md](docs/VALIDATION.md). Стабильный релиз и Windows CAD не объявляются выполненными.

## Итерация геометрических отношений — 25.10.2026

План разделения работ и критерии: [ITERATIONS.md](docs/ITERATIONS.md). Измерения и границы: [EVALUATION.md](docs/EVALUATION.md).

- Внедрены обрезанные планарные контуры с общей изометрией/отражением и отверстиями, группы аналогов формы, пар стенок и связанных аналогов.
- Материал проверяется точками и пересечениями BRep вдоль контрольных трасс. Нативная фикстура с узкой полостью доказала необходимость лучевой проверки.
- Второй пример может задать пару стенки либо связанный повторяющийся узел. Проверяются форма, размеры и общее размещение всех граней; исключения отбрасывают противоречащие гипотезы.
- В нативном preview добавлен устойчивый контур последнего включённого уровня; заливка остаётся 35%. Порядок, PgUp/PgDown, два примера, повтор узла, OK/Cancel и отсутствие остаточной графики проверены на отдельном документе macOS.
- Размеченный синтетический корпус и замороженный baseline внедрены. 134 Python-теста проходят; реальный STEP-корпус, Windows, большая геометрия и полная матрица Exclude остаются открыты.
- Логические поверхности из фрагментов реализованы как ограниченное [офлайн-исследование](docs/SURFACE_GROUPS.md), в нативный поиск не включены.

## 0. Инициализация — выполнена

- Изучены текущие исходники Perfora: manifest 1.0.1, нативная команда, чистое геометрическое ядро, Fusion adapter и удержание event handlers.
- Исследованы API и сценарии выбора, создан `docs/API_RESEARCH.md` с первичными источниками.

## 1. Проверка технического пути в Fusion — частично выполнена

Работать в одном отдельном несохранённом документе по `docs/VALIDATION.md`.

- Проверить исходное выделение при `commandCreated`: если оно теряется, перенести snapshot в menu handler с документом и проверкой актуальности.
- Проверить добавление одного пункта в меню и однородные примеры из одного тела.
- Проверить заполнение результата в activate, смену гипотезы и уровня сходства, отсутствие рекурсивных событий.
- Доказать перенос выбора после destroy → customEvent; при необходимости скорректировать синхронизацию со штатным Select по наблюдаемому поведению.
- Проверить OK, Cancel, прерывание, повторный запуск, остановку дополнения и смену документа до idle. Доказать отсутствие изменений модели.

Готово, когда реальное выделение после закрытия команды сохраняется и используется штатным Fillet/другой операцией, а отмена возвращает исходные примеры. Записать Fusion version, ОС, результаты и задержки. Unit-тесты этот этап не закрывают.

Базовые рёбра/грани, Magenta, PgUp/PgDown, OK/Cancel и неизменность модели проверены на macOS. Оставшаяся матрица — в `docs/VALIDATION.md`.

## 2. Удобное уточнение намерения — ядро и нативный сценарий реализованы

- Добавление положительного примера в открытом диалоге и исключение нежелательного элемента.
- Вывод короткого объяснения вместо обязательного выбора критериев.
- PgUp/PgDown и Similarity расширяют/сужают единое ранжирование всех сущностей исходного типа тела. Колесо штатное; поля Preview нет. Технические критерии остаются в Refine.
- Расширить негативные примеры корпуса: одинаковая площадь при разной форме, разные диаметры, вал рядом с отверстием, противоположные нормали, короткие/вырожденные рёбра.

Готово, когда обычные задачи решаются через пример и одно уточнение, а выбранная гипотеза объясняет каждый пример и исключение. Проверить с пользователем на его деталях; автоматическая «точность намерения» без размеченного корпуса не заявляется.

Офлайн-часть: неизменяемые снимки, явные критерии, ранжирование, исключения, история, Linked/More/Less, кратчайшие пути и точный ограниченный matcher регионов. Веб-демо не создаётся по указанию пользователя.

## 3. Семантика CAD

- Внедрить модель [INTENT_MODEL.md](docs/INTENT_MODEL.md): аналоги формы → непосредственная пара стенки → связанные аналоги; гипотезы намерения с проверяемыми объяснениями.
- Для стенок проверять параллельность, локальный зазор, перекрытие и материал между гранями. Близость центров не является доказательством.
- Внутренние цилиндры и типы отверстий по ориентации, петлям и соседству.
- Скругления/фаски и касательные цепочки, затем повторяющиеся группы граней.
- Обеспечить работу на STEP без опоры на исходную историю построения.

Каждый распознаватель получает корпус положительных и ложнопохожих примеров и отдельную CAD-проверку. Радиус сам по себе не считается распознаванием отверстия.

## 4. Component occurrences и производительность

- Поддержать тело внутри компонента, включая повёрнутые/вложенные occurrences. Область остаётся конкретным выбранным телом конкретного экземпляра.
- Проверить общую систему координат для направлений, сохранность proxy и отсутствие выбора соседнего экземпляра.
- Измерить чтение, ранжирование и подсветку на плотной перфорации Perfora, включая тысячи рёбер. Кэш ограничить одной сессией/ревизией тела.
- Улучшить порционную обработку и отмену при необходимости; Fusion API остаётся на основном потоке, worker может считать только числовые снимки.
